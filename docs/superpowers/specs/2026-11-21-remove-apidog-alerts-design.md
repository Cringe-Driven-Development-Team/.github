# Удаление алертов Apidog

## Цель

Вывести из эксплуатации интеграцию Apidog → Telegram на VPS3. Граница работы
охватывает сервис `webhook-alerts`, его настройки в `infra` и webhook target
проекта Apidog. Контракт API проекта и его остальные интеграции живут отдельно.

## Варианты для SQLite

1. Сохранить историю Apidog, исключить неотправленные карточки из очереди
   и закрыть для них ручной `retry`. История доступна для диагностики, а сервису
   нужны условия для исключения этих записей.
2. Удалить записи Apidog из рабочей базы одноразовой миграцией. Владелец выбрал
   этот вариант, включая удаление истории уже отправленных карточек из SQLite.
   Удаление ограничено рабочей базой webhook-сервиса. Telegram-сообщения и
   существующие резервные копии находятся за этой границей.

## Сервис и данные

- Удалить маршрут `POST /webhooks/apidog`, проверку его подписи, опрос Apidog API,
  форматирование карточек и настройки отдельного Telegram-бота. Обновить тесты,
  Docker smoke test и действующий runbook. `POST /webhooks/apidog` возвращает
  `404`. `GET /health` и подписанный `POST /webhooks/github` доступны.
- При открытии существующей SQLite выполнить версионированную миграцию в одной
  транзакции до запуска worker. Сначала удалить строки `outbox`, у которых
  `origin_type = 'delivery'` и `origin_id` указывает на доставку с
  `source = 'apidog'`. Затем удалить сами доставки, включая raw webhooks,
  события опроса и отметку начала мониторинга. `origin_type` ограничивает
  удаление даже при совпадении числовых ID доставок и групп ревью. Миграция
  использует включённые внешние ключи SQLite.
- Проверить обновление базы со смешанными записями Apidog и GitHub, в том числе
  со сгруппированным ревью и релизной карточкой. После миграции и повторного
  запуска должны остаться все GitHub-записи, их связи, статусы и границы
  релизной активации. Удалённая карточка Apidog недоступна для `retry`.

## Доведение до прода

- Отключить webhook target, который доставляет на `/webhooks/apidog`. Перед
  выкладкой образа с миграцией сделать штатный согласованный снимок SQLite.
- Выкатить новый образ webhook-сервиса через Auxiliary CD. После подтверждения
  его версии применить обновлённую роль `hooks` и убрать из `vault_hooks_env`
  настройки Apidog, включая токен и тему его Telegram-бота. Обновить проверки
  Ansible и действующий runbook. Такой порядок нужен, потому что текущий образ
  требует настройки Apidog при запуске.
- На VPS проверить запущенный образ, `/health`, отсутствие Apidog-переменных в
  окружении, `404` на старом маршруте и отсутствие записей Apidog в SQLite.
  Подтвердить приём GitHub-события и отправку Telegram-карточки, сохранение
  рабочих маршрутов ревью и алертов релизов фронтенда и бэкенда.
