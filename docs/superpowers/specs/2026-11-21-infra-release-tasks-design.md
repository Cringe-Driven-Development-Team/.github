# Задачи в алертах выкаток Infra и VPS3

## Цель

Показывать в теме **Infra / Alerts** задачи и изменения между предыдущей успешной
выкаткой и целевой версией. По формату использовать блок задач из алертов Backend.

## Источники данных

- Для общей Infra найти последнюю подтверждённую успешную выкатку Infra в
  `production` до начала текущей попытки и сравнить её SHA с текущим SHA в репозитории
  `infra`. История статусов Deployment и результат проверенной production job
  позволяют отличить успех от ошибки и отмены. Более поздний `inactive` сохраняет
  уже подтверждённый успех.
- Для выкатки VPS3 находить предыдущее успешное применение того же сервиса и
  сравнивать `source_sha` образов в `.github`. В списке учитывать PR, затрагивающие
  каталог этого сервиса или общие файлы, участвующие в публикации его образа.
  При инициализации VPS3 сохранять текущую карточку с SHA конфигурации infra.
- Список берётся из всего диапазона коммитов. Название и ссылка на связанный GitHub
  Issue имеют приоритет. Если у PR нет связанного Issue, используем название и
  ссылку PR. Одна задача, связанная с несколькими PR, появляется один раз.
  Сбор изменений по одному PR текущего SHA покрывает только последний merge и
  не подходит для выкаток с несколькими PR.

## Карточки

- Список показывается на старте и в итоге для того же диапазона. При ошибке или
  отмене заголовок **Планировались изменения** даёт понять, что это состав попытки.
  Например, при `0e89eb5 → 430053a` в списке будет «DevOps. Очистить остатки прежней
  интеграции вебхуков» со ссылкой на infra#173, у которого нет связанной задачи.
- Показываем до трёх ссылок. Если изменений больше, даём ссылку на полный диапазон
  сравнения. При повторной выкатке того же SHA показываем «Новых изменений нет».
- При неизвестной базовой версии или ошибке чтения GitHub карточка продолжает
  отправляться с подтверждёнными данными. Полный список выводится при подтверждённом
  диапазоне. Тема, кнопка логов, очередь и дедупликация остаются частью той же карточки.

## Приёмка

- Выкатка с несколькими PR показывает задачи из всех входящих PR, включая PR без
  связанного Issue. Падение промежуточной выкатки не сдвигает базовый SHA.
- Старт и итог используют одну пару версий даже при поздней доставке событий.
  Тесты покрывают повтор того же SHA, ошибку API и выбор базы отдельно для
  `webhook-alerts` и `githubbot`.
- Изменение реализуется в `services/webhook-alerts` репозитория `.github`. После
  штатной выкатки сервиса сверяем список с реальным диапазоном в карточке Infra.
