# GitHubBot: короткая справка

## Согласованное поведение

В PR #68 добавить `/help`: одно сообщение со списком команд и короткими описаниями на русском. Без примеров, дополнительных правил, кнопок и ссылок. Пользователь подтвердил этот вариант перед слиянием PR.

Доступ прежний: только настроенные Telegram ID в разрешённой общей группе, в любом её топике; в личке и посторонних чатах бот не отвечает. Поддерживается обычное адресование `/help@имя_бота`.

## Подходы

Выбран один компактный ответ существующим обработчиком команд. Расширенная справка с примерами была предложена и отклонена пользователем. Справку в личке также не добавляем: пользователь выбрал нынешний доступ. Новые интерфейсы и зависимости не нужны.

## Содержание

- `/help` — список команд.
- `/issue` — создать задачу в Backlog.
- `/close` — закрыть задачу.
- `/assign @username` — добавить исполнителя.
- `/assignme` — назначить себя.
- `/unassign @username` — снять исполнителя.
- `/tosprint` — перенести задачу в текущий спринт.
- `/sprint` — показать спринт команды.
- `/sprint @username` — показать задачи человека в текущем спринте.

## Реализация и границы

Использовать существующие парсер, очередь и доставку ответа; `/help` не обращается к GitHub и Projects. Справка отвечает в том же чате и топике. Дополнительные аргументы отклоняются короткой подсказкой формата. Эти технические детали — решение реализации, содержание и доступ согласованы с пользователем.

Сохранить исправление команд со ссылкой из #68. Не менять формат `/sprint`, другие команды, регистрацию команд через BotFather, конфигурацию и runtime credentials.

## Приёмка

Настроенный участник получает одно сообщение по `/help` и `/help@имя_бота` в любом топике группы. В ответе только девять указанных строк; отсутствуют кнопки, примеры и сетевые обращения к GitHub. Посторонние пользователи/чаты, личка и команды другому боту остаются без ответа. Повторная доставка использует существующий сохранённый ответ.
