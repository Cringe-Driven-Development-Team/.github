# Смена спринта: итоги, перенос хвостов, план

Дата: 2026-09-26
Статус: спека

## Зачем

Спринт — поле-итерация `Sprint` на доске Scrumban (`https://github.com/orgs/Cringe-Driven-Development-Team/projects/1`): неделя с понедельника по воскресенье (Sprint 1 — 14–20.09, Sprint 2 — 21–27.09, Sprint 3 — 28.09–04.10).

1. Смену спринта никто не видит: GitHub сам делает текущей итерацию, в чьи даты попадает сегодняшний день, событий «спринт начался / закончился» нет ни в Actions, ни в вебхуках.
2. Незакрытые задачи GitHub в новый спринт не переносит: встроенные автоматизации доски (auto-close, item closed/reopened, PR merged и т. п.) итерации не трогают. На 26.09 в Sprint 2 — 13 задач не в Done; с 28.09 они останутся в завершённом спринте и пропадут из представления текущего.

Решение: в понедельник утром бот переносит хвосты прошлого спринта в текущий и пишет в чат итоги и план.

## Где живёт

- `scripts/sprint.sh` — вся логика: чтение доски, решение, перенос, сообщение.
- `.github/workflows/reminders.yml` — новый шаг «Смена спринта» в том же job, что напоминания, перед ними. Отдельный cron не нужен: утренний запуск уже есть, и защита от отключения расписания общая.
- `tests/sprint.sh` — тесты по образцу `tests/reminders.sh`.

`scripts/reminders.sh` не меняется.

## Когда срабатывает

Шаг запускается:

- в плановом утреннем запуске — `github.event.schedule == '0 7 * * *'` (10:00 МСК);
- при ручном запуске с новым входом `sprint: true` (`workflow_dispatch`, по умолчанию `false`) — для проверки.

В остальных запусках (15:00, 20:00, ручной без флага) шаг не выполняется.

У шага `if: ${{ !cancelled() && (...) }}`; у шага напоминаний — `if: ${{ !cancelled() }}`: падение одного шага не отменяет другой.

### «Сегодня»

Дата по Москве: `TZ=Europe/Moscow date +%F`. Для тестов — env `TODAY=YYYY-MM-DD`.

### Итерации

Из конфигурации поля `Sprint` берутся все итерации — `iterations` и `completedIterations` — и классифицируются по датам сами, без опоры на то, какие GitHub считает завершёнными:

- итерация занимает дни `startDate … startDate + duration − 1`;
- **текущая** — та, в чьи дни попадает сегодня;
- **прошлая** — та, чей последний день раньше сегодняшнего, самая поздняя из таких.

### Решение

1. Нет прошлой итерации — ничего не делаем.
2. Хвосты прошлой итерации — задачи с `Sprint` = прошлая, которые не сделаны (см. ниже), и не в архиве доски.
3. Нет текущей итерации (перерыв или следующий спринт не заведён):
   - хвосты есть — сообщение «⚠️ Sprint 2 закончился, а следующего спринта на доске нет: N задач не перенесены» с пингом `OPS_PING` (YarikMix) и кнопкой на доску;
   - хвостов нет — ничего.
4. Текущая итерация есть:
   - хвосты есть (первый день или понедельничный запуск был пропущен) — сообщение и перенос;
   - хвостов нет, сегодня первый день — сообщение только при `ANNOUNCE_EMPTY=true`, иначе тишина;
   - хвостов нет, не первый день — ничего.

`ANNOUNCE_EMPTY` (env) — истинно только у планового утреннего запуска с первой попытки (`github.event.schedule == '0 7 * * *' && github.run_attempt == '1'`, задаётся в `reminders.yml`). Ручной запуск с `sprint: true` и повтор упавшей попытки (`run_attempt` > 1) получают `false`: если хвостов не осталось, «всё сделано» не постится по новой — иначе каждая проверка и каждый ретрай дублировали бы этот итог. Хвосты остались — сообщение и перенос идут независимо от `ANNOUNCE_EMPTY`, это не повтор, а реальная работа.

### Сделано

Задача сделана, если выполнено любое:

- `Status` = `Done`;
- содержимое — закрытая задача (`Issue.state = CLOSED`) или закрытый / смерженный PR (`PullRequest.state = CLOSED | MERGED`).

Всё остальное (Backlog, Ready, In progress, In review, без статуса) — хвост. Черновики доски (`DraftIssue`) — только по статусу. Элементы без содержимого (задача удалена или недоступна токену — `content: null`) не считаются и не переносятся.

## Перенос

Сначала уходит сообщение (см. «Сообщение») — список хвостов и план в нём построены заранее, как если бы перенеслись все. Только после того, как Telegram подтвердил доставку, начинается сам перенос: каждому хвосту — мутация

```graphql
updateProjectV2ItemFieldValue(input: {projectId, itemId, fieldId, value: {iterationId}})
```

с id текущей итерации. Статус, исполнители и остальные поля не меняются. Мутации идут по одной; сбой одной не останавливает остальные — в логе `::warning::`.

Если Telegram отклонит сообщение, до мутаций дело не доходит вовсе: доска остаётся нетронутой (см. «Ошибки»). Если сообщение ушло, а часть мутаций всё же не прошла — после цикла переноса одно короткое дополнительное сообщение в тот же топик:

```
⚠️ Не перенесены в Sprint 3 — перенесите руками:
• backend #20 Backend. CI CD. Интеграция с BFF на VPS · Backlog · без исполнителя
[Открыть доску]
```

По строке на каждую непереехавшую задачу — тем же форматом, что и в основном списке хвостов. Код выхода — 0: перенос в целом состоялся, доска просто требует ручной правки по паре задач.

## Сообщение

Одно, в общий топик (`TELEGRAM_TOPIC_ID`), с кнопкой «Открыть доску» → URL доски. Уходит раньше переноса (см. «Перенос»), поэтому список хвостов и план считаются так, будто перенесутся все, — без пометок о сбоях: сбой мутации отражается только в отдельном дополнительном сообщении.

```
🏁 Sprint 2 закрыт · 21.09–27.09
сделано 5 из 18
перенесено в Sprint 3 — 13:
• infra #1 Подготовить конфигурацию Ansible и Pulumi · In review · <пинг iRedTea>
• backend #16 Реализовать API ручки пользователей · In review · <пинг GrayMouse9>
• frontend #27 Frontend. Подготовить дизайн систему · Ready · <пинг ManInTheCoat>
• backend #20 Backend. CI CD. Интеграция с BFF на VPS · Backlog · без исполнителя
…и ещё N

🚀 Sprint 3 · 28.09–04.10
16 задач: GrayMouse9 4 · iRedTea 4 · MrDuckVC 3 · ManInTheCoat 2 · без исполнителя 3
[Открыть доску]
```

- Даты — `ДД.ММ`, первый и последний день итерации.
- «сделано X из Y»: Y — все задачи прошлой итерации (без архивных), X — сделанные.
- Хвостов нет — вместо блока «перенесено…» строка `всё сделано 🎉`; на первый день это сообщение уходит только при `ANNOUNCE_EMPTY=true` (см. «Решение»).
- Строка хвоста: сторона (`frontend` / `backend` / имя репозитория — как в `telegram.yml`), номер, заголовок — ссылкой на задачу; статус (`без статуса`, если пуст); исполнители — упоминаниями через `TELEGRAM_USER_MAP` (кто не в карте — текстом), нет исполнителей — `без исполнителя`. Черновик — `черновик · <заголовок>` без ссылки.
- Порядок хвостов: In review, In progress, Ready, Backlog, без статуса; внутри — как отдала доска.
- В списке до 20 строк, дальше `…и ещё N` (лимит Telegram — 4096 символов).
- План: «N задач» — все задачи текущей итерации после переноса, при условии что переедут все хвосты (без архивных); разбивка по исполнителям логинами текстом, по убыванию числа, задача с несколькими исполнителями считается у каждого; `без исполнителя K` — в конце, если есть.
- Все заголовки и логины экранируются (`&`, `<`, `>`).

## Токен и данные

- `ADD_TO_PROJECT_PAT` (env `PAT`, уже передаётся в job): читает доску и пишет в неё. Недоступен — `::warning::ADD_TO_PROJECT_PAT недоступен — смена спринта не проверена`, шаг завершается успешно.
- Константы в начале скрипта: владелец и номер доски (`Cringe-Driven-Development-Team`, `1`), имя поля (`Sprint`), статус «сделано» (`Done`), порядок статусов, лимит строк (20), `OPS_PING`.
- Задачи доски читаются GraphQL-запросом с пагинацией по 100 (`items(first: 100, after: …)`): id, `isArchived`, содержимое (`Issue` / `PullRequest`: номер, заголовок, url, state, репозиторий, исполнители; `DraftIssue`: заголовок, исполнители), значение поля `Sprint` (`iterationId`), значение `Status`.

## Ошибки

- Доска не прочиталась (GraphQL-ошибка или нет поля `Sprint`) — `::error::` и выход с кодом 1: запуск «Напоминаний о ревью» становится красным, и следующий запуск сообщит о нём в «🚨 Сбои уведомлений» (эта проверка уже есть). Шаг напоминаний выполняется независимо. Мутации ещё не запускались.
- Telegram отклонил основное сообщение — `::error::`, выход 1, как в остальных скриптах; поскольку сообщение уходит раньше переноса, ни одна мутация к этому моменту не выполнена — доска нетронута.
- Сбой части мутаций — см. «Перенос»: основное сообщение уже отправлено, после цикла переноса уходит короткое дополнительное с непереехавшими задачами; код выхода — 0.

## Тесты (`tests/sprint.sh`)

Заглушка `gh`: GraphQL-запрос чтения — фикстура (итерации, задачи), без `--paginate` отдаёт только первую страницу (ловит потерю флага); мутация — запись `item iteration project field token` в журнал (`token` — значение `GH_TOKEN`), по env — отказ для заданных `itemId`. Заглушка `curl` — общая `tests/stub-curl.sh`, включая `TG_REJECT` для имитации отказа Telegram.

- первый день спринта, есть хвосты: мутации для всех хвостов и только для них (id проекта/поля и токен в журнале — те же, что в фикстуре); сообщение: «сделано X из Y», список с пингами без пометок о сбоях, порядок по статусу, план с разбивкой, кнопка;
- первый день, хвостов нет, `ANNOUNCE_EMPTY=true`: «всё сделано 🎉», мутаций нет;
- первый день, хвостов нет, `ANNOUNCE_EMPTY=false` (ручной запуск/повтор): тишина, мутаций нет;
- закрытая задача не в Done и смерженный PR — сделаны, не переносятся;
- архивная задача не считается и не переносится;
- черновик в хвостах: строка без ссылки, переносится;
- второй день, хвосты есть (понедельник пропущен): перенос и сообщение;
- второй день, хвостов нет: тишина, мутаций нет;
- последний день текущего спринта (не первый), в нём есть незакрытая задача: она не хвост прошлой итерации — тишина, мутаций нет;
- нет текущей итерации, хвосты есть: «⚠️ … не перенесены» с пингом владельца, мутаций нет;
- нет прошлой итерации: тишина;
- Telegram отклонил основное сообщение: код 1, ни одна мутация не выполнена;
- сбой одной мутации: остальные перенесены, `::warning::`, основное сообщение без пометок о сбое, отдельное сообщение «⚠️ Не перенесены в …» только с непереехавшей задачей, код 0;
- больше 20 хвостов: 20 строк и «…и ещё N», перенесены все 22;
- PAT пуст: тишина и `::warning::`, код 0;
- доска недоступна: `::error::`, код 1, сообщений нет;
- заголовок с `<b>` и `&` экранирован; исполнитель вне карты — текстом;
- «сегодня» по Москве: `TODAY` на границе суток.

Шаг в `reminders.yml` проверяется `tests/lint.sh` (actionlint).
