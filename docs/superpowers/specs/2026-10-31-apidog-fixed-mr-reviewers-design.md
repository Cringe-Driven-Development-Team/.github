# Постоянные ревьюверы в уведомлении об открытии Apidog MR

## Зачем

Участники Telegram-треда Apidog должны видеть и получать упоминания двух
постоянных ревьюверов — Александра Батовкина и Ярослава Михалева — при открытии
каждого MR. Сейчас карточка показывает только создателя MR. У MR #40066 Apidog
возвращает в `reviewerIds` лишь Александра, поэтому этот список не подходит для
требуемой постоянной пары.

## Подходы

- **Выбран:** хранить упорядоченную пару имён и Telegram ID в настройке сервиса,
  формировать строку для каждого `MR_OPENED`. Список не зависит от назначения
  ревьюверов в Apidog и не требует нового запроса к API. ID остаются в Vault.
- Показывать `reviewerIds` из Apidog и всегда добавлять Ярослава. Это отражало бы
  назначение в конкретном MR, но не гарантировало бы присутствие Александра.

## Поведение

- В карточке `MR_OPENED` после «Создатель MR» появляется строка
  «Ревьюверы: Александр Батовкин, Ярослав Михалев» в этом порядке. Оба имени —
  Telegram-упоминания, если они ещё не упомянуты в этой карточке. Повторное имя
  остаётся текстом, чтобы один человек получил не более одного пинга.
- `MR_CLOSED` и `MR_MERGED`, кнопки, тема, очередь и правила отправки не меняются.
- `APIDOG_MR_REVIEWERS` — обязательный при включённой отправке JSON-массив из
  двух объектов `{ "name": "…", "telegramId": "…" }`. Сервис проверяет непустые
  имена, корректные и разные Telegram ID. Значение хранится в `vault_hooks_env`;
  ID Александра можно взять из существующей карты Apidog, ID Ярослава нужно
  получить и добавить в Vault до выкладки.
- Тесты проверяют оба упоминания, порядок, отсутствие повторного пинга при
  совпадении создателя и ревьювера, а также прежний вид закрытого и слитого MR.

## Границы

В карточке указывается постоянная пара, даже если Apidog назначил иных
ревьюверов. Настройка не меняет права или список ревьюверов самого MR.
