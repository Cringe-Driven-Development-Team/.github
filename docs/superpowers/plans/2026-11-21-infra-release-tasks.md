# План добавления задач в алерты Infra и VPS3

> **Для исполнителя.** После выбора владельцем применять `superpowers:executing-plans` или `superpowers:subagent-driven-development`. Шаги отмечать в журнале выбранного режима.

**Цель.** Показать задачи и PR, входящие в выкатку Infra или отдельного сервиса VPS3, в обеих карточках **Infra / Alerts**.

**Архитектура.** По истории GitHub Deployments определяем предыдущую успешно применённую версию относительно начала текущей production job. Обогащение карточек использует сравнение SHA и чтение связанных Issue по образцу Backend.

**Стек.** Bun, TypeScript, GitHub REST и GraphQL, SQLite outbox.

**Спецификация.** [Задачи в алертах выкаток Infra и VPS3](../specs/2026-11-21-infra-release-tasks-design.md).

## Общие условия

- Источник базовой версии — успешно завершившийся production Deployment `task=infra-alerts` того же типа. Для VPS3 учитывается только совпадающий сервис и `operation=deploy`.
- Пересылаемые сообщения остаются в теме `14389` и используют имеющиеся ключи попытки, верификацию подписанных событий и SQLite.
- Формирование списка — необязательное обогащение с ограничением времени запросов по действующему GitHub reader. Ошибки GitHub API сохраняют обычную карточку и её кнопки. Успех, ошибка и отмена продолжают определяться существующей проекцией.

## Что проверить при ревью

- Более поздний `inactive` не скрывает реальный `success`, а промежуточная ошибка не становится базой.
- Запоздавший итог не видит успешный Deployment, состоявшийся после начала текущей попытки.
- Папки второго сервиса VPS3 не добавляют его PR в список первого. Общие файлы публикации учитываются.
- Один Issue из нескольких PR виден один раз, PR без Issue виден со своим названием.
- Одинаковые SHA пропускают сетевое сравнение, а неполные данные GitHub не притворяются пустым диапазоном.

### Task 1: Подтверждённый диапазон и связанные изменения

**Файлы.** `services/webhook-alerts/src/infra-releases.ts`, новый `src/infra-release-changes.ts` для расчёта списка, общий код чтения изменений в `src/release-api.ts` либо `src/github-api.ts` по существующим границам, `tests/infra-release-changes.test.ts` и задетые тесты Backend.

**Интерфейс.** Расчёт возвращает `InfraReleaseChanges | undefined`, где `InfraReleaseChanges = { base: string; head: string; compareUrl: string; entries: { kind: 'issue' | 'pr'; title: string; url: string }[] }`. Вход — проверенная текущая попытка и её Deployment, включая время начала production job, тип и метаданные образа. `undefined` означает, что полный список подтвердить не удалось.

- [ ] Написать тесты выбора базы. Задать успешный Infra `0e89eb5` с поздним `inactive`, промежуточный `failure`, текущий `430053a` и более новый `success` после `started_at`. Ожидать базу `0e89eb5` и тот же ответ при проекции результата. Проверить независимые прошлые SHA `webhook-alerts` и `githubbot`, инициализацию и отсутствие подтверждённой базы.
- [ ] Написать тесты сборки списка. Два PR с одним Issue должны дать одну ссылку, третий PR без задачи — свою ссылку. Для VPS3 исключить PR, меняющий только каталог второго сервиса, и оставить PR с файлом публикации, общим для обоих. Для `base === head` ожидать `entries: []` без запроса compare. При 5xx или неполной пагинации ожидать `undefined`.
- [ ] Запустить `bun test tests/infra-release-changes.test.ts` из `services/webhook-alerts` и зафиксировать падение новых проверок. Реализовать выбор предыдущего Deployment с подтверждённым `success` и успешной проверенной job до начала текущей попытки. Сверять репозиторий, путь workflow, job и attempt по существующему механизму. Исключить текущую попытку даже после завершения. Выбирать базу по времени завершения подходящей job.
- [ ] Переиспользовать обход compare, PR по commit и `closingIssuesReferences` из Backend. Ограничить новые репозитории `infra` и `.github`. Для VPS3 проверять файлы каждого PR по каталогу нужного сервиса и путям соответствующего publisher workflow, в том числе общим файлам сборки. Подтвердить количество страниц и целостность сравнения. Собрать ссылки на Issue и PR по контракту.
- [ ] Прогнать новый файл, тесты Backend release API и `bun run typecheck`. Закоммитить API и его тесты.
